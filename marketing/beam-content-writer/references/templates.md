# Article Templates + On-Page Checklist

Pick the template by cluster. Structures are proven patterns; deviate only when SERP intent demands it (and say why).

## Template A — Alternative page ("[Competitor] Alternative") — clusters C10, C2

1. **Hook**: acknowledge why they're searching. Name the real complaints (verified via research: pricing, US-only, identify-only, setup burden). 2–4 sentences.
2. **TL;DR verdict box**: 3–4 lines. Who should stay with [Competitor], who should switch to Beam, one honest sentence about each. AI engines quote this block.
3. **What [Competitor] does well** — honest, specific. This section buys credibility for everything below it.
4. **Where it falls short** — every claim evidenced (reviews, docs, pricing page, dated).
5. **Beam as the alternative** — the loop story (see → find → charm), person-level, 60–80% match range, setup in one snippet, pricing from $0/free plan. Map each Beam strength to a shortfall above.
6. **Comparison table**: rows = price entry, person vs company level, geographic coverage, outreach included?, setup time, compliance. Columns = Competitor, Beam.
7. **Switching / getting started**: 30-minute setup, free plan, no card.
8. **FAQ** (3–5 PAA questions).
9. CTA block (product register).

## Template B — Vs page ("X vs Y" incl. referee pages) — cluster C11

1. **Hook + TL;DR**: one-line verdict per tool, by use case ("choose X if..., choose Y if..."). No winner-takes-all.
2. **Comparison table near the top.**
3. **Deep dive per dimension**: identification level (person/company), match rate, outreach workflow, integrations, pricing, compliance.
4. **Verdict by persona**: founder/solo, small team, sales team.
5. **Referee pages only**: "the third option" section introducing Beam AFTER treating both tools fairly. Beam pages ("beam vs X"): still be fair; overselling kills the page.
6. **FAQ + CTA.**

## Template C — Category education / pillar — clusters C1, C5, C9, C13, C14, C15

1. **Hook with a number** (97% anonymous, 1–3% conversion, 60–80% match rates).
2. **Plain-English answer to the query within the first 150 words** (featured snippet + AI answer target).
3. **How it actually works** — mechanics, honestly including limits.
4. **Step-by-step section** the reader can execute today.
5. **How to choose a tool** (criteria: person vs company level, match rate, price, compliance, outreach loop) — Beam mentioned as one honest option, criteria framed where Beam wins.
6. **FAQ + single CTA.**

## Template D — Platform/integration long tail — clusters C16, C17

1. Hook: the platform-specific situation ("your Shopify store gets traffic, Shopify analytics shows you numbers, not names").
2. What's possible on [platform] + what's not.
3. Install walkthrough on that platform (one snippet, where to paste it).
4. What you see after 30 minutes.
5. FAQ + CTA.

## CMS validator checklist (the blog editor checks these — EVERY article must pass ALL before delivering)

The founder's CMS runs this exact validation. A draft that fails any item is not done:

- [ ] Focus keyword set (declare it in frontmatter as `target_keyword`)
- [ ] Keyword in title
- [ ] Keyword in URL slug
- [ ] Keyword in the intro (first paragraph, naturally)
- [ ] Keyword in at least one subheading (H2 or H3)
- [ ] SEO title length between 30 and 60 characters
- [ ] Meta description set (150–160 chars)
- [ ] Has subheadings (H2/H3)
- [ ] Word count ≥300 (Beam targets are 1,200+ anyway; never below 300)
- [ ] Has at least one internal link (Beam standard: 3+)

## On-page checklist (run on EVERY article before delivering)

- [ ] Title ≤60 chars, primary keyword in the front half, says something a human would click
- [ ] Meta description 150–160 chars, keyword + concrete reason to click
- [ ] Slug: short, lowercase, keyword-based
- [ ] Exactly one H1; primary keyword appears in first 100 words naturally
- [ ] H2s cover the sub-intents (check People Also Ask); keyword variants in 2–3 H2s, not all
- [ ] 3+ internal links (pillar + nearest money page + one existing blog post), descriptive anchor text
- [ ] 1–2 external links to genuinely authoritative sources (not competitors' blogs)
- [ ] Comparison table present on A/B templates; TL;DR box present on A/B
- [ ] FAQ: 3–5 real PAA questions, answers ≤80 words each, suggest FAQPage JSON-LD
- [ ] All Beam claims traceable to product-facts.md; all competitor claims dated
- [ ] Voice check against voice-and-style.md hard bans (no em dashes, no banned phrases)
- [ ] One mid-article CTA max + one closing CTA
